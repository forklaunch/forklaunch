BREAKING: an HMAC-signed request (`auth: { hmac }`, internal service-to-service routes) is now accepted only once. Its timestamp must be within 5 minutes of the server clock in either direction, its signature is compared in constant time, and its nonce cannot be reused inside that window; a missing or malformed timestamp is a 401 and an unknown key id a 403. Who is affected: callers whose clock is more than 5 minutes off, and hand-written signers that reuse a nonce or cache the `authorization` header across requests (the framework signers, `generateHmacAuthHeaders` and `universalSdk({ hmac })`, already sign every request freshly). Fix: sync clocks, and sign every request, including retries, with a new timestamp and nonce; the window is configurable with `hmac: { secretKeys, maxSkewMs }`. Multi-instance apps must act: used nonces are remembered in process memory by default, which protects a single process only, so an app running several copies needs a shared store, `hmac: { secretKeys, nonceStore: redisTtlCache }`. `TtlCache` gains an optional atomic `putRecordIfAbsent`, implemented by `RedisTtlCache` with `SET NX PX`, and the nonce store uses it; a cache without it still works but falls back to a non-atomic check followed by a write. A custom store can implement `HmacNonceStore` (`claim(key, ttlMs)`). `maxSkewMs` and `nonceStore` are also accepted by `bindRuntimeAuth`. The HMAC failure debug log no longer contains the expected signature or the request body.
