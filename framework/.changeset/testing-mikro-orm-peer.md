`@forklaunch/testing` takes `@mikro-orm/core` from the application (peer dependency `^7.2.5`) instead of pinning its own copy, and `@forklaunch/internal` no longer depends on it (nothing in it imports MikroORM). 1.3.1 and 1.2.36 pinned 7.2.10, so an application on `@forklaunch/core` 3 with MikroORM 7.2.5, including apps generated by the current CLI, installed two copies on its next install and its entity types stopped matching (`Types have separate declarations of a private property '_meta'`). Applications must list `@mikro-orm/core` themselves; generated applications already do.
