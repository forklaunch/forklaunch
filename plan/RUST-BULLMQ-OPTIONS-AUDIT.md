# BullMQ worker options and interoperability audit

Scope: the repository's `BullMqWorkerProducer`, `BullMqWorkerConsumer`,
`BullMqWorkerOptions` and tenant-isolation helpers, compared with the Rust
`forklaunch-worker-redis/bullmq` adapter. The reference runtime is pinned
BullMQ **6.3.10**; the native protocol sources are vendored from
`bullmq-official` **1.3.5** with documented ForkLaunch patches. This is an audit
of this compatibility baseline, not a claim about later upstream releases.

## Public wrapper behavior

| TypeScript surface | Rust mapping | Evidence and boundary |
| --- | --- | --- |
| `queueOptions.connection` | `BullMqOptions.queue.connection` | URL, credentials, database, TLS and client certificates use native Redis connection options. The wrapper shares connection/prefix with its worker. JavaScript ioredis instances and callbacks have no native representation. |
| `queueOptions.prefix` | `queue.prefix` | Both wrappers override it from the platform tenant environment. Redis ACLs enforce the boundary; a prefix alone does not. |
| `retries`, `backoffType`, `interval` | `retries`, `BackoffStrategy::{Fixed,Exponential}` | Override job defaults for both single and bulk submission. Actual cross-language retries and per-attempt callbacks are checked, including zero attempts (one execution with no retry). |
| `enqueueJob`, `enqueueBatchJobs` | `enqueue_job`, `enqueue_batch_jobs` | Event `id` is the job **name**; IDs are generated by BullMQ. Batches validate all native event IDs before dispatch. Backend failures may leave partial writes. |
| `processEvents([event])` | Native per-job processor | Both process one event at a time per execution slot. Native concurrency is separately configurable through `worker`. |
| `failureHandler` | `run_until_with_failure_handler` | Receives original data for processing and preprocessor failures, even when removal deletes the Redis job. Native error detail is sanitized. |
| `peekEvents` | Consumer/producer `peek_events` | Returns waiting/active bodies in the same order; excludes delayed, prioritized and terminal jobs. This mirrors the TS wrapper and is not an all-state listing. |
| `start`, `close` | `connect`, `run_until`, bounded `close` | Native construction is idle; execution is explicit and shutdown drains. Native stops on the first storage error; TS explicitly stops on NOPERM. |

## Queue options

| Pinned TypeScript option | Native behavior |
| --- | --- |
| `defaultJobOptions` | Typed `JobOptions`; wrapper overrides attempts/backoff and clears default job IDs as the TypeScript wrapper does. See job policy coverage below. |
| `streams.events.maxLen` | `streams_max_len_events`, default 10,000; writes the shared `opts.maxLenEvents` metadata used by BullMQ's approximate stream trimming. |
| `skipMetasUpdate` | `skip_metas_update`; construction skips metadata HSET and preserves existing settings. This does not make later job operations read-only. |
| `skipVersionCheck` | Default native queue/worker construction checks the reported Redis major version is at least 5; opt-out skips INFO. The wrapper propagates the queue setting to its worker. Missing/invalid version information fails closed. Native does not reproduce TS recommended-version/eviction warnings or alternate-backend version detection. |
| `blockingConnection` | Deprecated and unused by pinned TypeScript; no native option is needed. |
| `skipWaitingForReady` | No equivalent. Native construction awaits connection establishment under the wrapper's operation deadline. |
| `telemetry` | No BullMQ-compatible telemetry object or per-job trace-context propagation adapter. Native worker metrics and ForkLaunch OTLP are separate surfaces. |
| `settings.repeatStrategy`, `repeatKeyHashAlgorithm` | Custom callbacks/hash algorithms are unsupported. The protocol API exposes the checked built-in scheduler behavior. |

Metadata preserves the native `library` identifier and writes the shared
`version` field with that native identity. It does not impersonate the TS library
version. The native `get_version` accessor retains its historical `library`
lookup; use `get_meta` for shared metadata written by either implementation.

## Job policies and operational coverage

The actual-TypeScript fixture exercises default merging; timestamps; retained
failure reasons and bounded stack histories; job-size and log-retention limits;
zero-attempt and fixed/exponential retries; bounded event-stream trimming; delay, priority and LIFO; concurrency/rate limits;
boolean/count/age/limited lazy retention; stalled recovery and start limits;
removed-job failure observers; simple/TTL/debounce/active keep-last deduplication;
and duplicate event IDs in both producer/consumer directions.

The scheduler fixture exercises built-in interval and cron/timezone behavior,
limits, replacement/removal, persisted scheduler metadata, retention and
cross-language execution. Legacy repeat options are not an alternative to the
BullMQ 6 scheduler API. Flow/parent dependency methods exist in the upstream
native protocol surface but are not exposed by the ForkLaunch worker wrapper;
this audit does not assert complete cross-language flow conformance.

Arbitrary upstream `JobsOptions` are not a promise of wrapper parity. In particular,
BullMQ-specific telemetry metadata/custom callbacks and ioredis Cluster/Sentinel
objects remain outside the native typed options. Native protocol structs can
represent additional advanced features beyond the checked wrapper profile;
applications must not treat serde acceptance of unknown JSON option fields as
support for those options.

## Tenant boundary and failure behavior

`REDIS_KEY_PREFIX` takes precedence over `FORKLAUNCH_REDIS_KEY_PREFIX`; both trim
ECMAScript whitespace and trailing colons. Missing prefixes retain dedicated-cache
behavior. Native additionally rejects control characters, hash tags and prefixes
over 256 bytes. Both producer and consumer use the forced prefix. Restricted
Redis users in the fixture may access only owned key/channel patterns, cannot
change ACLs/configuration, and cannot enumerate or flush the server.

NOPERM returns one sanitized native isolation error and stops consumption;
retries cannot repair an ACL denial. Operation and drain deadlines bound storage
failures. ACL-denied INFO and HSET cases verify the version-check opt-out and
metadata-write opt-out independently. No credentials or denied key names are
included in native public errors.

## Remaining implementation requirements

Full upstream-option parity still requires explicit native designs and tests for
BullMQ telemetry/context hooks, custom scheduler callbacks/hash strategies,
readiness options, and Cluster/Sentinel integration. Complete flow/parent
interoperability also needs a separate fixture. These remain part of the broader
production-worker parity gate in the implementation plan. They are not satisfied
by exposing the upstream `inner()` handle or by completing this audit.

## Validation entrypoints

- `cli/tests/rust_bullmq_parity.mjs`: actual repository TS wrappers and native adapter against an isolated Redis ACL namespace.
- `cli/tests/rust_bullmq_scheduler_parity.mjs`: actual scheduler interoperability.
- `cli/tests/rust_bullmq_protocol_unit.sh`: pinned protocol library tests against an owned isolated Redis server; script-cache tests may flush that server's script cache.
- `cli/tests/rust_bullmq_worker_runtime.sh`: relocated generation/lifecycle and generated worker plus HTTP/MCP startup.

The source reference files are
`blueprint/implementations/worker/bullmq/{producers,consumers,domain}` and the
pinned package's `interfaces/queue-options.d.ts`, `interfaces/base-job-options.d.ts`,
`interfaces/advanced-options.d.ts`, and `types/job-options.d.ts`.

Validation receipt (2026-10-12): full wrapper interoperability, focused options
and approximate stream trimming, 67 isolated protocol tests, strict adapter
Clippy, packaged source inventory, relocated generated worker lifecycle and
HTTP/MCP startup all passed. See the implementation-plan checkpoint for scope.
